## 视觉规格

以参考图中 macOS 默认鼠标指针为尺度参照，将图片按约 2 倍像素密度换算为 CSS 尺寸：整体宽 336 px；输入胶囊/圆形按钮高 40 px；任务卡最小外高 56 px；卡片间距 12 px。收起后双按钮胶囊宽 80 px，主要字号 13 px、图标 18 px、发送按钮 24 px。尺寸已按用户反馈从第一版整体缩小约 30%。配色按 DSH UI 样式看板调整：中性白色磨砂表面、灰黑文字、细灰边框，主要操作使用 DSH 蓝色。保留背景模糊和线条 SVG 图标。

颜色依据为看板消费的 `ui-theme/src/styles/design-platform.css` 浅色语义令牌：主要文字 `#0F1115`，次要文字 `#61666B`，辅助文字 `#81858C`，信息按钮 `#4176E6`（悬停 `#679EFE`），成功 `#22C55E` / `#E6FAED`，错误 `#EC1313`。扩展 Shadow DOM 使用局部语义变量映射这些值，不依赖宿主网页注入 DSH 样式。白色表面采用 96% 不透明度，是胶囊磨砂效果的局部处理；本次沿用浅色模式，不根据宿主网页猜测主题。

轮廓保留两端的正圆圆弧，只在圆弧与直线交接处加入短段 G2 过渡，已移除上一版会改变整个端部的超椭圆。胶囊圆弧半径为 20 px，任务卡为 28 px。每个端部中间 130° 保持严格的圆弧，仅靠近上下直线的各 25° 区域由三次 Bézier 过渡连接。两端对应圆弧平移后位于同一个正圆上。

过渡段与直线连接处曲率为 0，与圆弧连接处的切线方向、曲率均与圆弧匹配（曲率 1/r）。路径使用 SVG 圆弧命令与短三次曲线构成；背景裁切与描边来自同一几何定义。缩放、收起/展开时按元素实际尺寸更新路径。单个圆形按钮仍为正圆。

新增几何验收读取浏览器实际使用的轮廓，验证：圆弧横纵半径相等；同侧上下圆弧共享圆心；短曲线在圆弧端匹配切线和曲率、在直线端曲率为零。不会仅凭 CSS 属性名称判断 G2。

输入宽度有 280 ms 过渡，任务卡有淡入位移动画；系统开启“减少动态效果”时关闭这些动画。关键帧不能确定原版的动画时长和中间插值；本次没有实现截图中的液态融合形变。

## 统一阴影

所有独立浮层共用 DSH `InputBar` 的 `elevation-soft` 柔光：`0 4px 16px rgba(0,0,0,.03)` 与 `0 0 24px rgba(0,0,0,.03)`。入口、展开/收起胶囊、任务/结果/错误卡、菜单和状态提示保持一致，保留现有轮廓描边。

阴影由独立的 shadow-only SVG 底层绘制，沿用 G2 轮廓，两个 Gaussian blur 的标准差分别为 8/12 px。不会被内容的 `clip-path` 或滚动容器裁掉，也不会通过给毛玻璃祖先加 `filter` 改变背景模糊。动画期间跟随实际位置和透明度，收起态内嵌箭头不重复叠加阴影。

## 实时流

改写过程中，模型正在产生的思考内容实时显示在**任务卡的第二行**，也就是原来写“正在思考…”的那一行。任务卡保持两行摘要高度、不会展开，输入行也不占用；答案不会提前出现在这一行。扩展为每次任务开一条 `dsh-stream` 端口，Host 侧走 `POST /v1/rewrite/stream` 的 SSE：

- `ready`：记录绑定会话；`reset`：模型重试，该行回到“正在思考…”，清空上一轮文本；
- `thinking`：实时写入该行（模型的 reasoning 增量，保留末尾 160 字）；
- `text`：答案不进状态行，该行只显示“正在生成结果…”；
- `done`：该行显示结果本身（单行、超出省略号），展开后该行隐藏、正文接续同一段文字；
- `error`：该行显示错误信息。

### 展开只是露出更多行，位置不动

结果正文始终是紧贴标题的那一个元素：收起时用 `-webkit-line-clamp:1` 截成一行（带省略号），展开时解除裁剪、露出全部内容（超过 160px 内部滚动）。因此标题与正文首行在两种状态下坐标完全相同——实测卡片、标题、正文的位移都是 0，卡片只是向下长高（56px → 约 102px）。收起态卡片高度固定为 56px，端部保持正圆；正文没有分隔线、边框和焦点方框。

结果是可编辑的替换文本，必须保留全文才能正确替换，所以正文用的仍是完整文本，只是不再重复渲染开头。

“思考”内容只在模型真的产生 reasoning 增量时才有。本机实测同类请求两次分别得到 0 和 41 个 `thinking` 增量；没有思考内容时不会伪造摘要。关闭胶囊、取消或断开端口都会中止 Host 上的一轮任务。`chrome.runtime.connect` 不可用时回退到原有一次性 `/v1/rewrite`。

## 收起后的状态

从展开态收起（点卡片或对钩）都应该回到**完成时的同一个胶囊**：56px 高、标题 + 一行带省略号的结果 + 对钩，按钮行与原始编辑器一起隐藏。收起时 `editingResult` 会一起复位，并清掉文本框保存的高度；否则文本框会带着最多 160px 的高度溢出到胶囊外，和页面文字叠在一起。

结果卡片使用不透明底色：页面里的文字、灰底元素不再透过卡片显示（之前 96% 半透明会把它们透出来，看起来像文字重叠和“半块灰”）。输入胶囊仍保留磨砂透明。

## 完成标记

绿色对钩是任务确认标记，位置随卡片状态走：

- **胶囊（折叠）**：停在摘要行右侧；点击即确认并关闭整个插件 UI。
- **展开**：下移到整张卡片的右下角（复制/替换之后），不再和标题、正文抢宽度；点击先收回胶囊形态，结果不会丢。

摘要行与操作行会为标记预留宽度（分别是 58px / 42px），因此文字不会被盖住。

## Markdown

结果区按 DSH 的策略渲染 Markdown，而不是显示原始符号：DSH 用 mdast 的 GFM 语法（表格、删除线、任务列表、自动链接），扩展没有打包器、也不能把模型返回的 HTML 注入页面，因此用同一套 GFM 子集**构造 DOM 节点**，源码里的 HTML 保持字面文本——这与 mdast 默认不允许危险 HTML 的行为一致。

支持范围：ATX 标题、段落、粗体/斜体/删除线、行内代码、围栏代码（带语言标签）、有序/无序/嵌套列表、任务列表、引用、分割线、GFM 表格、`http(s)`/`mailto` 链接（其他协议保持原文）、裸链接。样式沿用看板令牌：行内代码用 `--dsh-neutral`，代码块与表头用 `--dsh-tip`，链接用 DSH 蓝 `#4176E6`；字号在 336px 胶囊内按比例缩小，不再是 14/24 的正文级排版。

渲染视图默认展示，点击后切到原始文本编辑器（Escape 或失焦返回渲染视图）。复制与替换始终使用原始文本，因此渲染只影响阅读，不影响写回内容。

## 结果区焦点

展开后的结果正文是纯文本排版：既没有 `textarea:focus-visible` 的 2px 方框，也没有上下分隔线或背景块。焦点指示完全去掉（用户要求），正文与上面那一行是同一段连续文字。

编辑态与展示态使用同一套排版：左右内距 16px、字号 13px、行高 20px，宽度也一样，点击进入编辑时文字不跳、不换行错位。注意 `<textarea>` 是替换元素，`width:auto` 会退回它的固有宽度（看起来卡片被压窄一半），所以显式写成 `calc(100% - 32px)` 配合两侧 16px 外边距。

任务卡的标题行不参与 hover 变色：`#task-summary` 虽然是 `<button>`，但已覆盖全局 `button:hover` 的灰底，避免标题区域整块变灰。

折叠态下正文那行在距右侧 58px 处截断，不会伸到对钩下面；对钩在胶囊里垂直居中，展开时才移到右下角。

## 描边

每个浮层只保留一条 1px 发丝描边，颜色 `rgba(0,0,0,.1)`：跑道型（输入胶囊、任务卡）由 SVG 轮廓绘制，圆形按钮和加号菜单由 CSS `border` 绘制，两者不叠加。输入聚焦时轮廓改为品牌蓝。状态提示条不描边。

跑道型卡片曾出现**完成态外框描边整条消失**：`#task` 上的 `overflow:hidden` 会把子元素裁到 padding box，而描边正好画在最外 1px，于是被完全裁掉。现在改由 `clip-path` 负责裁切内容，`overflow` 保持 `visible`。胶囊端部的圆弧半径与直线段的分界、描边与背景裁切来自同一几何定义，卡片变高（展开结果）时上下两个圆角弧仍以各自圆心绘制。

## 截图未明确的行为与插件补充

以下为本次实现选择，不声称能从静态截图直接确认：

- **加号菜单**：展示已选文字，提供桌面打开、连接设置、取消任务和关闭入口。原来的“语音输入”标签实际打开设置，本次移除该误导入口。
- **收起/展开**：编辑按钮展开输入；输入已收起时，下箭头控制任务卡显示；收起不丢草稿或任务。Escape 先关菜单，再收起输入、隐藏任务，最后关闭。
- **结果详情**：输入展开时返回结果直接显示详情；输入收起时只显示完成卡，点击卡片再展开详情。
- **任务标题**：使用提交的修改要求，长文本省略显示、悬停可看全文。现有 Host 没有标题生成接口，因此没有假造参考画面中的自动标题缩写。
- **进度**：“开始任务 / 思考”是本地等待阶段；实际完成与错误以 Host 响应为准，未新增服务端进度流。
- **单任务**：当前改写运行期间保留新输入草稿，禁用重复提交；未扩展成多任务队列。
- **网页范围**：从选区或可编辑插入光标启动，并定位在其附近。这是浏览器插件，不会成为桌面菜单栏下的全局常驻窗口，也未新增跨应用日历等能力。

## 入口显示逻辑与无选区生成

| 页面状态 | 入口行为 | 操作 |
| --- | --- | --- |
| 可编辑文本框/富文本获得输入光标，尚未打字 | 显示 4 秒，到期后不被普通光标事件反复唤起 | 描述要求后生成新段落，核对后“插入” |
| 主动选中非空文字 | 显示入口，包括用户打字后再选择文字 | 基于选中文字生成，核对后“替换”；只读/跨块可复制 |
| 开始打字、粘贴、删除或中文输入法组词 | 立即隐藏；本次输入会话内不在无选区时打扰 | 主动选中文字仍可唤出改写 |
| 点击空白处、编辑器失焦或切到其他窗口 | 立即隐藏自动提示，丢弃未打开的入口目标 | 不会因浏览器保留旧选区而重新出现 |
| 点击插件自身入口 | 保留选区/插入点，展开输入 | 聚焦插件不会丢失原编辑位置 |
| 尚未提交时点击页面空白 | 关闭输入界面，不残留编辑图标 | 已提交任务仍按原逻辑继续 |

无选区时，插件保留零长度选区和编辑器快照，插入时验证页面、原文和位置仍有效。可在已有文本中间或空白编辑器中插入，前后文字不被覆盖。Host 支持 `mode: insert` 与空 `text`，用户创作要求原样作为 human query，选区、页面信息通过 `agent.inject` 的插件快照传入，不发送光标前后的编辑器全文。空选区不提供旧桌面改写入口。

## 会话绑定

加号菜单可新建、绑定已有会话和解除绑定。首次提交自动新建，后续提交与重试续用当前文档绑定。绑定按连接配置、Tab、frame 与完整文档 URL 隔离，保存在 `chrome.storage.session`，支持页面刷新与 worker 重启恢复；不跨浏览器重启或扩展重新加载。确认替换后，下一轮选区更新为刚写回的文本。

改写规则走 `systemPrompt.section`，页面与选区走 `agent.inject`（`source.kind=plugin`），只有人的 query 走 `agent.followup`（`source.kind=user`）。被其他 live agent 占用的 session 不接管。当前最近会话列表展示 ID，可直接输入 ID 绑定。
